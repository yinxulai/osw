# 三步搭好网关

首次启动会进入一条三步引导。它是**直线**的，顺序不能换，因为前一步的产物是后一步的前提：先决定请求怎么选路 → 再决定拿什么上游跑 → 最后知道往哪里填。

<Callout title="不选也能跑" type="note">
第一步不选也行：内置已经有一套默认策略在按它跑。引导只是想让你换个起点。
</Callout>

## 第一步：选路

引导第一步是「请求按什么选路？」，让你在两种路由模式里挑一个。两份配置各自独立保存，来回切换不会丢掉另一边的东西。

- **工作流编排**：在画布上把节点连成链路。
- **路由规则**：一张从上往下读的规则表。

详细对比见[请求选路](/routing)。这一步还可以直接从**内置方案**里挑一套直接生效，之后去「智能路由」页接着改。

## 第二步：加上游

引导第二步「请求发到哪里？」用来加第一个上游供应商：

1. 选一个**预设**（预设会把接口地址填好），或选「自定义供应商」。
2. 填供应商名称与 **API Key**（无需鉴权的上游可留空）。
3. 点**拉取模型**，从这家勾选要用的模型。

拉取后记得勾选具体模型——供应商下没有模型时，请求没有可落点。模型管理页的完整能力见[供应商与模型](/providers)。

## 第三步：接客户端

引导第三步「把工具指到这个地址」给出本机服务地址与要填的值。同一块卡片还有另一半答案：机器上已经装了客户端时，去[客户端配置](/client-config)点**全部生效**，OSW 会改那个客户端自己的配置文件，并且每次改动前先留一份可回退的版本。

参考表：

| 你的客户端 | Base URL |
| --- | --- |
| OpenAI 兼容（Chat Completions / Responses） | `http://127.0.0.1:9300/v1` |
| Anthropic | `http://127.0.0.1:9300` |

<Callout title="人人都踩的坑" type="warning">
Anthropic 客户端会**自己**在地址后面追加 `/v1/messages`，所以 Base URL 到端口为止。多加一个 `/v1` 会变成 `/v1/v1/messages`，代理不认识，得到一个 404。
</Callout>

模型名随你写：`default`，或任意非空名字。OSW 会把它换成实际选中渠道的真实模型 ID。客户端非要 API Key 的话，填任意占位符即可——真正的密钥是按供应商注入的。

## 验证接上了

服务是否活着：

```bash
curl http://127.0.0.1:9300/v1/models
```

客户端里发一句话，然后去[请求记录](/request-logs)：出现这条请求，就说明接上了。

监听地址与端口在**设置 → 网络 → 监听服务**里改；保存后代理会自动切到新端口。
