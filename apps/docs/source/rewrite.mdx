# 请求重写

**请求重写**在转发路线上加一层可编排的改写：请求发出前、响应回来前，按规则改请求头、请求体或响应内容。

<Callout title="只处理非流式 JSON" type="warning">
重写只作用于**非流式 JSON**请求。流式（SSE）与非 JSON 内容不参与重写。
</Callout>

## 两个阶段

| 阶段 | 时机 | 作用对象 |
| --- | --- | --- |
| **请求** | 请求发往上游之前 | 请求头、请求体 |
| **响应** | 上游返回之后、回给客户端之前 | 响应头、响应体 |

## 一条规则

一条规则由「匹配条件 + 操作」组成：

- **匹配**：命中哪些请求才应用（方法与路径等）。
- **操作**：
  - `set`：设置一个字段。
  - `append`：追加一个值。
  - `remove`：移除一个字段。
  - `replace`：替换字段中匹配的部分（支持正则）。

每个操作指定目标（请求头 / 请求体字段 / 响应）与值。值可以用**模板**引用请求上下文，例如内置版本号 `OSW/<version>`。

## 内置模板

页面上直接给了几个常用模板，选择即套用，之后可继续编辑：

| 模板 | 做什么 |
| --- | --- |
| 修改 User-Agent | 把 UA 改成 `OSW/<version>`。 |
| 移除请求头 | 删掉指定的请求头。 |
| 设置请求字段 | 在请求体里设置一个字段。 |

## 调试

规则列表按顺序生效。每条的开关可以单独关掉，用于二分定位是哪条改坏了请求。改动保存后立即生效，新请求即可看到效果。

<Callout title="响应阶段的改动会影响客户端" type="note">
响应重写发生在回给客户端之前，客户端看到的是改写后的内容——排障时要注意这一点。
</Callout>
