# 不支持的边界

OSW 是一个**本地 LLM 代理**，它有清楚的边界。下面这些是**故意不做**的，不是没做完。

## 网络与访问

- **没有系统级代理**：OSW 不做全局流量接管，只服务显式把 Base URL 指过来的客户端。
- **没有远程访问**：设计上就在本机跑，监听默认绑 `127.0.0.1`。把它暴露到局域网需要你自己承担风险（它不带鉴权）。
- **管理服务只监听本机**：管理 API 固定只绑 `127.0.0.1`，需要在别的机器访问请走 SSH 隧道。

## 协议

- **不支持 Gemini 的 `/v1beta/models/*`**：请用 OpenAI 兼容或 Anthropic 形态接入。
- **协议转换是兼容层**：默认不转换。只有显式开启后，某端点才可能接住其他协议的请求，且部分参数可能丢失。

## 路由与故障转移

- **故障转移只发生在一组之内**：一个逻辑模型下挂的模型，或一条显式开启转换的渠道。它**不会跨组兜底**——那属于路由的职责。
- **流式开始后不再拼接**：流式中断即中止，不会把多个渠道的输出拼起来。

## 协作与同步

- **没有团队协作 / 多用户权限**：这是单机工具。
- **没有账号体系**：不引入登录，云同步用的是你自己的凭据。
- **云同步只做编码，不做加密**：base64 让文件不一眼可读，不是保密手段（见[配置云同步](/observability/cloud-sync)）。
- **没有自动 / 定时同步**：上传与拉取都是你手动触发的一次动作，也不做冲突合并。

## 请求重写

- **只处理非流式 JSON**：流式（SSE）与非 JSON 内容不参与重写（见[请求重写](/upstreams/rewrite)）。
- **响应阶段当前关闭**：因为流式响应无法在事件级改写、而它占绝大多数流量，响应阶段整段关闭——编辑器不提供，保存或试跑带响应阶段的规则会被拒绝（见[请求重写](/upstreams/rewrite)）。

## 观测

- **正文按原样记录**：捕获**不限制大小**，请求体会被完整读进内存；请求体也不脱敏（见[请求记录](/observability/request-logs)）。

## 更新

- **大版本不支持自动更新**：包含破坏性变更（数据与配置不再沿用）的版本只能手动下载安装。
- **macOS 不能自动安装**：因为 ad-hoc 签名，只能检查更新并打开 DMG 下载页。

如果你的需求落在这些边界之外，欢迎到 [GitHub 仓库](https://github.com/yinxulai/osw) 提 issue 讨论。
