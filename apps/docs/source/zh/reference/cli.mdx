# 命令行

命令行形态与桌面端共用同一份数据目录与配置，适合无头环境、容器或脚本化运行。

<Callout title="命令行尚未发布" type="warning">
命令行形态**目前未发布，也未经过人工验收**：包未对外公开，「osw」也没有可供安装的分发渠道。下面写的是它**已经实现的能力**，现阶段只有从源码构建才能运行。日常使用请以**桌面端**为准。
</Callout>

## 用法

```bash
osw [命令] [选项]
```

| 命令 | 说明 |
| --- | --- |
| `start` | 启动服务（**不写命令时的默认行为**）。 |
| `stop` | 停止由本 CLI 启动的实例。 |
| `status` | 输出运行状态、监听地址、数据目录与版本。 |
| `user` | 管理登录账号：`list` / `add <用户名>` / `remove <用户名>`。 |
| `version` | 输出版本号。 |

## 选项

| 选项 | 说明 |
| --- | --- |
| `--data-dir` | 数据目录。 |
| `--host` | 代理监听地址。 |
| `--management-host` | 管理面监听地址。缺省跟随回环；填 `0.0.0.0` 就是把控制台开放给网络。 |
| `--proxy-port` | 代理端口。 |
| `--management-port` | 管理端口。 |
| `--password-stdin` | 从标准输入读口令（**仅 `user add`**）。 |
| `--web` | 由管理服务托管控制台（默认开启）。 |
| `--no-web` | 不托管控制台，只提供 HTTP API。 |
| `--json` | 以 JSON 输出（**仅 `status`**）。 |
| `--help` | 显示帮助。 |
| `--version` | 输出版本号。 |

<Callout title="管理面默认只监听本机" type="note">
管理面缺省只监听 `127.0.0.1`，且不要求登录——桌面与个人本机就该是这样。要在别的机器上打开控制台，用 `--management-host 0.0.0.0`：这时**默认要求账号登录**（非回环监听下默认开启「要求登录」）。
</Callout>

## 启动

启动后会打印控制台地址、代理地址、管理服务地址与数据目录，按 `Ctrl+C` 停止。

<Callout title="--host 会暴露无鉴权代理" type="warning">
代理监听在非回环地址上时，同网络的其它设备可以直接访问它，而它**不带鉴权**（代理侧不校验调用方身份，鉴权是管理面的事）。只想本机使用，就别传 `--host`（默认只监听 `127.0.0.1`）。
</Callout>

## 装到服务器上（server 模式）

默认形态是「本机自用」：两个端口都只监听回环，管理面不要求登录。把它装到一台服务器上、让几个人通过浏览器共用，就是 **server 模式**——它不是一个单独的开关，而是由**管理面监听地址**推导出来的一整套行为。

### 形态

只要管理面不监听回环地址，下面三件事同时成立：

| 维度 | 回环（默认） | 非回环（server 模式） |
| --- | --- | --- |
| 「要求登录」的缺省值 | 关 | **开** |
| 一个账号都没有时 | 照常启动 | **拒绝启动** |
| 浏览器拿到的凭证 | 入口 HTML 里注入本次启动的 token | 只有登录换来的会话 cookie |

- 「要求登录」是**普通设置**（设置 → 访问控制），server 模式下可以关掉；但**零账号拒绝启动**与这个开关无关——它只看监听地址。
- 代理端口（默认 `9300`）在两种形态下都一样**不校验调用方身份**。管理面的登录保护的是「谁能改配置、看密钥」，不是「谁能消耗额度」。

### 第一次部署

四条命令，顺序不能改（第三条会因为没有账号而失败）：

```bash
# 1. 建第一个账号。服务不需要在跑——它直接写配置库。
osw user add admin

# 2. （可选）确认账号已写进去
osw user list

# 3. 管理面开到网络上，代理仍只监听本机
osw start --management-host 0.0.0.0

# 4. 浏览器打开 http://<服务器地址>:9301/ 登录
```

口令**不接受命令行参数**，只能交互输入（不回显）或走标准输入，给脚本与容器初始化用：

```bash
printf '%s' "$PASSWORD" | osw user add admin --password-stdin
```

命令行参数会原样留在 shell 历史与进程列表里，而这是这台服务器的管理口令，所以刻意没有 `--password <值>` 这种写法。

<Callout title="先有账号，才能监听非回环地址" type="note">
`osw start --management-host 0.0.0.0` 在**没有任何账号**时会拒绝启动，报错里直接给出建号命令：

```text
Refusing to listen on 0.0.0.0: no management account exists yet.
Create one first with `osw user add <username>`, or start once on 127.0.0.1
and create it from the web UI.
```

这条检查发生在**绑定端口之前**：非回环监听下「谁能连上端口」不再是边界，一个零账号的服务一开，任何人访问 `/api/settings/get` 就能读走全部密钥。没有「先开起来再从界面里建号」这种余地——界面上那个建号入口本身就要先能进得去。
</Callout>

### 账号

| 操作 | 在哪做 |
| --- | --- |
| 新建 | `osw user add <用户名>`（服务不用在跑） |
| 看列表 | `osw user list`，或设置 → 访问控制 |
| 改口令 | 只能在控制台的「访问控制」里 |
| 删除 | `osw user remove <用户名>`，或设置 → 访问控制 |
| 退出登录 | 控制台页脚 |

用户名与口令的规则（命令行与控制台一致）：

| 字段 | 规则 |
| --- | --- |
| 用户名 | 1–64 个字符，只允许字母、数字、`.`、`_`、`-` |
| 口令 | 至少 8 个字符，**不**强制大小写或符号 |

只卡长度不卡字符种类是刻意的：强制「必须有大写和符号」在真实世界里只会得到 `Password1!` 这种同时满足规则又好猜的口令。

几条要知道的：

- **新账号要重启服务才在面板里出现**：`osw user add` 写的是库，服务启动时已把「有没有账号」读进内存。提示原文就是「重启服务（osw stop && osw start）后新账号才会生效」。
- **最后一个账号删不掉**。删完就没人能登进来，只能去服务器上再用 `osw user add` 救一次。
- **登录状态活不过重启**：会话存在进程内存里（12 小时，勾「保持登录」30 天），服务一重启全部作废。这是刻意的——它是一次登录的临时事实，不是数据。
- 每个账号看到的都是**全部**配置与全部请求日志。没有角色、没有权限划分（见[不支持的边界](/reference/limitations)）。

### 监听地址与端口

| 选项 | 作用 | 默认 | 存在哪 |
| --- | --- | --- | --- |
| `--management-host` | 管理面监听地址 | `127.0.0.1` | 只属于**这次启动**，不写库 |
| `--management-port` | 管理端口 | `9301` | 同上 |
| `--host` | 代理监听地址 | `127.0.0.1` | 写进**设置**的默认值 |
| `--proxy-port` | 代理端口 | `9300` | 同上 |

<Callout title="--host / --proxy-port 会被界面里的设置顶掉" type="warning">
管理面的地址与端口只从命令行来，每次启动都要给。代理的地址与端口不是：`--host` / `--proxy-port` 只填**没有存过**的设置字段。一旦在设置页里保存过监听地址，「下次启动再传 `--host 0.0.0.0` 却不生效」就是必然结果——以设置页里的值为准，命令行也不是例外。要改代理监听地址，优先改设置页。
</Callout>

典型的两种用法：

```bash
# 只开管理面：几个人在同一台内网机器上用浏览器管配置，代理仍只给本机客户端
osw start --management-host 0.0.0.0

# 管理面和代理都开：内网里其它机器直接连代理
osw start --management-host 0.0.0.0 --host 0.0.0.0
```

后一种形态下 `start` 会往 stderr 打两行告警（代理端口不带鉴权、同网络内任何设备都能读写）。告警只提**代理**端口：管理面有自己的门，拿一句模糊的「无鉴权」把它一起算进去并不解决问题。

### 反向代理与 HTTPS

服务**没有内置 TLS**：它只会监听明文 HTTP。要给公网或团队用，就在前面套一层 nginx / Caddy / Cloudflare Tunnel，让反代终止 TLS。

反代只需要转发到一个上游（管理端口），静态控制台与 `/api/*` 都在它上面：

```nginx
server {
  listen 443 ssl;
  server_name osw.example.com;

  ssl_certificate     /etc/ssl/osw.crt;
  ssl_certificate_key /etc/ssl/osw.key;

  location / {
    proxy_pass http://127.0.0.1:9301;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;   # 少了这一行，cookie 不会带 Secure
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
  }
}
```

三件事必须对上，否则表现是「登录成功，但一直停在登录页」：

1. **`X-Forwarded-Proto`**：会话 cookie 的 `Secure` 属性由它决定（或由真实 TLS socket 决定）。反代终止了 TLS 却没传这个头，服务就以为自己在明文上，于是不加 `Secure`——能登上，但浏览器在 HTTPS 页面之外的行为不受约束；反过来，直接对着 HTTP 端口访问却带上 `Secure`，浏览器会**直接丢弃** cookie，登录静默失效。
2. **主机名前后一致**：cookie 的域就是页面的域。用 `https://osw.example.com` 打开，就必须用同一个域名访问（不能一会儿 `localhost:9301`、一会儿域名）。`SameSite=Lax` 下这是两个不同的站点，会话会悄无声息地丢。
3. **不要只转发页面路径**：`/api/*` 与静态产物同源，全站转发即可；单独给 `/api` 配一个上游很容易漏掉登录后前端跳转所需的其余路径。

<Callout title="别把管理端口直接挂到公网" type="warning">
明文 HTTP + 一个口令就是全部保护。没有速率限制、没有二次验证、没有账号锁定。公开部署前请确认：前面有 TLS 终止、防火墙只放行反代所需的地址、`--management-host` 绑定的是反代能到的那张网卡而不是 `0.0.0.0`（例如 `--management-host 127.0.0.1` 配本机反代）。
</Callout>

### 进程守护

`osw start` 是**前台进程**，`Ctrl+C` 收尾。没有 `--daemon`、也没有内置的 systemd 单元，用你系统的进程管理器托住它即可：

```ini
# /etc/systemd/system/osw.service
[Unit]
Description=OSW gateway
After=network-online.target

[Service]
Type=simple
User=osw
ExecStart=/usr/local/bin/osw start --management-host 0.0.0.0
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

`Restart=on-failure` 与 `Type=simple` 都成立：进程正常退出时退出码是 `0`，崩溃是 `1`，用法错误是 `2`。

<Callout title="osw stop 必须用同一个系统用户跑" type="note">
`stop` 靠数据目录下的 `runtime.json` 定位实例、靠 `management.token`（`0600`）过管理面的门。换个系统用户跑，读不到这两个文件，就只能 `kill`——那会跳过数据库与端口的收尾。同理，`--data-dir` 也必须与启动时一致。
</Callout>

### 安全清单

- **`management.token` 是 `0600`**：它随启动写入、随退出删除。读得到它的进程可以直接调管理 API，不需要登录。
- **代理端口没有调用方鉴权**：`--host 0.0.0.0` 等于把额度和重写规则交给同网段的任何人。只想让人用浏览器管配置，就别开 `--host`。
- **会话不是「永久的登录」**：清空浏览器数据、重启服务、改口令都会让会话失效。
- **每个账号能看全量数据**：包括所有供应商、明文导出的密钥和全部请求日志。给别人开账号前先想清楚这一点。
- **首次建号只有两条路**：服务器上的 `osw user add`，或临时用 `127.0.0.1` 启动一次、从界面里建。第二条用完记得停掉并以 server 模式重启。

### 这套形态下没有的东西

- **没有内置 TLS、没有内置反代**：自己套一层。
- **没有多租户**：账号只是「能不能进管理面」，不隔离数据。
- **没有 Docker 镜像**：装的是本机单进程，容器化要额外回答「数据目录怎么挂、密钥怎么给、端口怎么映射」。
- **`--no-web` 在 server 模式下没什么用**：没有控制台就没有登录页，账号只能靠 `osw user add`，配置也只能靠 API。它存在的意义是「只跑 API」的机器，不是「给别人用」的机器。
- **`status` / `stop` 只认命令行启动的实例**：桌面端不写运行时文件，它归自己的窗口与托盘管。

## 状态

```bash
osw status          # 人类可读
osw status --json   # 供脚本消费
```

状态包含：运行中 / 未运行 / 无响应、管理服务、代理地址、控制台、数据目录、版本、PID、启动时间。

几种提示值得留意：

- **端口没在监听**：进程还在，但代理端口没有监听——服务可能启动到一半就失败了。
- **版本漂移**：运行中的实例版本与当前 CLI 版本不一致。

## 停止

`osw stop` 向实例发出退出请求并做清理。若没找到运行中的实例，会清理失效的运行时文件；若实例没开启退出握手（或那个端口上其实是别的服务），会拒绝退出请求。

## 冲突处理

- **端口被占用**：停掉占用进程，或用 `--proxy-port` / `--management-port` 换端口。
- **已有实例在运行**：先用 `osw stop` 停掉；要同时跑两个，给其中一个 `--data-dir` 指定另一个数据目录。

## 错误码与文案

命令行输出的错误是本地化的。代理运行期的错误码会在[请求记录](/observability/request-logs)中展示，含义见[常见问题](/reference/troubleshooting)。
