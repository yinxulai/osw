# 数据目录与保留

OSW 的所有本地状态都放在一个**数据目录**里，默认 `~/.osw`。桌面端与命令行共用它。

## 两个数据库，职责不同

| 文件 | 存什么 | 删掉会怎样 |
| --- | --- | --- |
| `config-v1.db` | 供应商、模型、逻辑模型、路由、设置、客户端配置 | **会丢配置，值得备份** |
| `data-v1.db` | 请求记录、用量、运行日志 | 只丢历史，**删掉安全** |

<Callout title="要备份的是 config-v1.db" type="note">
换机器或重装前，备份 `config-v1.db` 就够了。`data-v1.db` 是可再生的观测数据。
</Callout>

## 一起放在数据目录里的

| 文件 | 用途 |
| --- | --- |
| `secrets.json` | 加密后的上游凭据等；权限受限。 |
| `telemetry-id` | 匿名安装标识（UUID v4，权限 `0600`）。 |
| `instance.lock` | 单实例锁。 |

## 目录位置

在**设置 → 数据 → 数据目录**里可以改数据目录；重启后生效。开发版固定用 `~/.osw-development`，不会碰到你的真实数据。

## 保留与清理

| 数据 | 默认 | 在哪调 |
| --- | --- | --- |
| 请求记录（元数据） | 永久 | 设置 → 数据 → 请求日志 |
| 请求内容（正文） | 7 天 | 设置 → 数据 → 请求日志 |
| 运行日志 | 见设置 | 设置 → 数据 → 日志保留 |

请求体与响应体内容默认会被记录，因此请求内容保留策略是控制数据膨胀的主要旋钮。详见[请求记录](/observability/request-logs)。

## 导出与迁移

- **供应商导出**：见[供应商与模型](/upstreams/providers)，可选是否含明文 API Key。
- **配置云同步**：用 GitHub Gist 在设备间同步配置，见[配置云同步](/observability/cloud-sync)。
