# Client configuration

The **Client configuration** page lets OSW edit local AI client config files directly, saving you from hand-copying the Base URL and model name.

![OSW Client configuration page listing the clients OSW can configure and what it writes.](/screenshots/en/light/client-config.png)

## Supported clients

OSW keeps a built-in registry of the AI clients it can configure. For each one it knows where the config file lives, what format it is in, and which keys point the tool at a provider. **A write touches only those keys** — every other key, comment and the file's original formatting is left as it is.

| Client | Protocol | Config files | What OSW writes |
| --- | --- | --- | --- |
| Claude Code | Anthropic Messages | `~/.claude/settings.json` | `env.ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`, the `model`, and every `ANTHROPIC_DEFAULT_*_MODEL` alias |
| Codex | OpenAI Responses | `~/.codex/config.toml` | `model`, `model_provider`, and the `[model_providers.osw]` table |
| VS Code | OpenAI Chat Completions | `chatLanguageModels.json` | a `Custom Endpoint` provider entry named `OSW`, with its model |
| OpenCode | OpenAI Chat Completions | `~/.config/opencode/opencode.json` | `model`, `small_model`, and the `osw` provider entry |
| Copilot CLI | OpenAI Chat Completions (BYOK) | `~/.copilot/osw.env` | `COPILOT_PROVIDER_BASE_URL` / `COPILOT_PROVIDER_API_KEY` and `COPILOT_MODEL` |
| Pi | OpenAI Chat Completions | `~/.pi/agent/settings.json`, `~/.pi/agent/models.json` | `defaultProvider`, `defaultModel`, and the `osw` provider entry |
| DeepSeek Harness | OpenAI Chat Completions | `~/.dsh/settings.yaml` | `agent-default-model`, and the `llm-pi-ai.providers.osw` route |

<Callout title="Copilot CLI is configured through the environment" type="note">
Copilot CLI points at a custom (BYOK) provider only through `COPILOT_PROVIDER_*` environment variables, so OSW delivers its address, key and model through a dedicated env file and sources it from your login shell.
</Callout>

## Auto-fill

Click **Auto-fill** for a client: it writes the access address and sets the current logical model as the model of the local provider named `osw`. **Each client gets exactly this one entry written**, and it is the single landing point inside OSW.

<Callout title="One entry per client" type="note">
Auto-fill does not walk every configured client — only the one you clicked. To change several at once, use "Generate & apply all" below.
</Callout>

<Callout title="The development build writes a different provider name" type="note">
A client's config file exists only once per machine, so the **development build** (`pnpm dev`) writes a different provider name than the production build: production writes `osw` / `OSW`, development writes `osw-dev` / `OSW Development`. That is what lets the two run side by side — clicking "Generate config" while developing no longer rewrites the production config you are actually using onto the development port.

Clients whose config can hold two provider entries side by side (Codex, OpenCode, VS Code, Pi, DeepSeek Harness) get the **other** entry written in development. Clients that cannot (Claude Code, Copilot CLI) are **skipped entirely** in development — there is nowhere to put a second address and model, so writing one would only overwrite your production config. Skipped clients are flagged as unsupported in this environment; you can still edit them by hand below.
</Callout>

## Generate & apply all

**Generate & apply all** in the top-right of the page header handles every configured client that supports writing, in one pass, and reports the result of each.

## Revert

**Every write is backed up first**, and each client keeps a history of revertible versions:

- Click **Revert** to undo auto-fill and restore the original file.
- The **History** section lists the points in time a client can be reverted to; you can preview, pick one manually, or delete a backup you do not want to keep.

<Callout title="Back up before writing" type="info">
Revert is based on the backup taken before the write, so the original content before the very first auto-fill is always recoverable.
</Callout>

## Manual configuration

If you would rather OSW did not touch files, fill in these two lines yourself:

```text
Base URL: http://127.0.0.1:9300          # Use this for Anthropic, no /v1
Base URL: http://127.0.0.1:9300/v1       # Use this for OpenAI-compatible
API Key:  any non-empty string           # Not checked locally, a placeholder is fine
Model:    any non-empty model name       # Use default if unsure
```

<Callout title="The API key is only a placeholder" type="note">
Auth is not checked locally, and the real secret is injected per provider. If a client demands a key, give it a placeholder.
</Callout>

## Verify

After configuring, send a message from the client, then go to [Request logs](/observability/request-logs): if the request shows up, you are connected.
